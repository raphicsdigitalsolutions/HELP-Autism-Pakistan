## 6. Actual Vercel Redirect Implementation

The Vercel deployment uses `vercel.json` as the authoritative routing configuration. The configuration now:

- Keeps `cleanUrls: false`, because page canonicals, internal links, and the sitemap intentionally use explicit `.html` URLs.
- Uses explicit permanent redirects (Vercel returns HTTP 308 for `permanent: true`) for every extensionless page slug and the legacy aliases listed in this map.
- Redirects to existing concrete `.html` destinations. No catch-all rewrite is used, so unknown routes can continue to reach the branded 404 page.
- Keeps `helpautismpakistan.com` DNS unchanged until management approves the production cutover.

The release verifier `scripts/verify_release.mjs` checks redirect destinations, page files, canonical URLs, sitemap entries, and local assets during the deployment build. Actual end-user delivery of a redirect should still be confirmed in the Vercel deployment after the build becomes ready.
